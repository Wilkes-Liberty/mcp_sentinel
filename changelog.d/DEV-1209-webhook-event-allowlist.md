section: Changed
---
Webhook event names are a hard allowlist (`mcp.entity.presave`, `mcp.entity.delete`, `mcp.anomaly.alert`). Unknown names are refused on settings save: the endpoint machine id is cut at 64 characters, each echoed name is cut at 128 characters, and only the first 3 names are listed (`, and N more` after that). Cuts are character-safe UTF-8 (`mb_substr` after `mb_scrub`), not raw bytes. `McpEventDispatcher::dispatch()` and `enqueueForEvent()` now drop unknown names: third-party callers of the `mcp_sentinel.event_dispatcher` service get a refused no-op that is audited. `dispatch()` accepts entity events only. The worker, requeue, and replay paths refuse a stored unknown `event_name` the same way, and the `webhook_event_refused` audit row names the delivery (and endpoint, cut at 64 characters, when known) for those stored-row refusals. Replay of a refused row tells the operator the event name was refused. Replay of a held or discarded row does not. A stored `mcp.entity.save` filter is still shown as stored and still needs the live name before anything else can be saved. Plain revert is clean; no update hook. Rows already marked failed with the refusal reason stay failed.
