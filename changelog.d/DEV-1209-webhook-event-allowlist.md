section: Changed
---
Webhook event names are a hard allowlist (`mcp.entity.presave`, `mcp.entity.delete`, `mcp.anomaly.alert`). Unknown names are refused on settings save (each echoed name is cut at 128 characters). `McpEventDispatcher::dispatch()` and `enqueueForEvent()` now drop unknown names: third-party callers of the `mcp_sentinel.event_dispatcher` service get a refused no-op that is audited. `dispatch()` accepts entity events only. The worker, requeue, and replay paths refuse a stored unknown `event_name` the same way, and the `webhook_event_refused` audit row names the delivery (and endpoint when known) for those stored-row refusals. Replay of a refused row tells the operator the event name was refused. A stored `mcp.entity.save` filter is still shown as stored and still needs the live name before anything else can be saved.
